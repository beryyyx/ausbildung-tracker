# Ausbildung Tracker

Локальное однопользовательское веб-приложение без аутентификации.
Помогает отслеживать заявки на Ausbildung в Германии, позже — вести Berichtsheft.

## Модули

1. **Заявки (`applications`)** — компания, должность, город, ссылка на объявление,
   дата отправки, статус, дедлайн, заметки. В работе: схема готова, UI ещё нет.
2. **Berichtsheft** — еженедельные отчёты во время обучения. Запланирован, не начат.
   Получит свой файл схемы `src/db/schema/berichtsheft.ts` и свою папку в `src/features/`.

## Стек

- Next.js 16 (App Router), React 19, TypeScript в режиме `strict`
- Tailwind CSS 4
- Drizzle ORM 0.45 + better-sqlite3 (SQLite), drizzle-kit для миграций
- ESLint (`eslint-config-next`)
- Node.js 24, пакетный менеджер npm

## Команды

```bash
npm run dev          # запуск в режиме разработки, http://localhost:3000
npm run build        # production-сборка
npm run typecheck    # tsc --noEmit
npm run lint         # eslint
npm run db:generate  # сгенерировать миграцию из изменений схемы
npm run db:migrate   # применить миграции вручную (обычно не нужно, см. ниже)
npm run db:studio    # Drizzle Studio: просмотр базы в браузере
```

Перед завершением любой задачи с кодом: `typecheck`, `lint`, `build` должны проходить.

## Структура папок

```
src/app/                 маршруты App Router (layout.tsx, page.tsx, ...)
src/db/index.ts          клиент Drizzle, единственная точка доступа к БД
src/db/schema/           схема: по файлу на модуль, реэкспорт через index.ts
src/features/<module>/   (планируется) логика модуля: queries.ts, actions.ts, components/
src/lib/                 общие хелперы без привязки к модулю
drizzle/                 сгенерированные SQL-миграции и meta/ — не редактировать руками
data/app.db              файл базы, в .gitignore
drizzle.config.ts        конфиг drizzle-kit
.env                     DB_FILE_NAME=data/app.db (шаблон в .env.example)
```

## База данных

- Доступ только на сервере через `import { db } from "@/db"`. Файл помечен `server-only`,
  импорт из клиентского компонента упадёт на сборке. `better-sqlite3` вне `src/db` не импортировать.
- Миграции применяются автоматически при первом обращении к `db` (при старте `next dev`).
  Отдельно запускать `db:migrate` не нужно.
- Изменение схемы: правим `src/db/schema/*.ts` → `npm run db:generate` → проверяем SQL
  в `drizzle/` → перезапускаем dev. Уже применённые миграции не удалять и не менять.
- `better-sqlite3` указан в `serverExternalPackages` в `next.config.ts`, не убирать.

### Соглашения по типам колонок

- Календарные даты (дата отправки, дедлайн): `text` в формате `YYYY-MM-DD`.
  У них нет часового пояса, а ISO-строки корректно сортируются.
- Моменты времени (`createdAt`, `updatedAt`): `integer` с `mode: "timestamp"`, unix-секунды.
  `updatedAt` обновляется Drizzle через `$onUpdate`, руками не ставить.
- Перечисления: `text` с `{ enum: [...] }` плюс CHECK-ограничение, без отдельных таблиц.
  Константа-массив в файле схемы — единственный источник правды.
- Необязательные поля nullable. Пустую строку из формы превращать в `null` до записи.
- Имена колонок в БД `snake_case`, в TypeScript `camelCase`.

### Статусы заявки

`draft` черновик → `sent` отправлено → `invitation` приглашение → `offer` оффер / `rejected` отказ.
Ключи хранятся в БД на английском, русские подписи задаются в UI-слое.

## Соглашения по коду

- Язык: идентификаторы и имена файлов на английском, комментарии и тексты интерфейса на русском.
  Строки UI держать в словарях/константах, а не рассыпать по JSX, чтобы позже перевести.
- Даты в интерфейсе показывать как `DD.MM.YYYY`, в БД хранить только ISO.
- Именованные экспорты. `export default` только там, где требует Next (`page.tsx`, `layout.tsx`, конфиги).
- Server Components по умолчанию. `"use client"` только для интерактивности и по минимуму.
- Мутации через Server Actions в `actions.ts` с `"use server"`. Вход валидировать через Zod
  (добавить пакет при первой форме). Чтение из БД — в `queries.ts` того же модуля.
- Страницы, читающие БД, не должны запекаться при сборке: данные меняются между запросами.
- Форматирование как в шаблоне Next: 2 пробела, двойные кавычки, точки с запятой, запятая в конце.
- Не коммитить `.env`, `data/*.db`, `.next/`.
